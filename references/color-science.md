# 色彩科学最小底座

内置配方采用统一参数意图，而不是商业软件同名滑杆值。核心公式和顺序如下：

- 曝光：线性光中 `L' = L × 2^EV`。
- Gamma 近似：`C' = C^(1/gamma)`；它只用于首版 SDR 风格近似，不代表相机曲线。
- 对比度：围绕中灰枢轴做缩放，再限制到合法范围。
- 饱和度：以亮度为轴混合，`C' = Y + s(C-Y)`。
- 白平衡：首版用受限通道增益近似暖冷与绿洋红；绝不把 App 的“色温 +20”解释为 20 K。
- 锐化：调色后使用轻量反遮罩；噪点和暗角最后处理。
- 曲线：使用输入、输出均为 0–1 的单调 PCHIP；强度按 `y'=x+k(y-x)` 从恒等曲线插值，避免非单调反相。
- HSL：只使用红、黄、绿、青、蓝、品红六个宽色带；它们不是语义肤色，也不等于某个 App 的橙色范围。

FFmpeg 顺序为：输入解释 → 基础亮度/Gamma/对比/饱和 → 单调曲线 → 暖冷与 tint → 青橙近似 → 宽 HSL 色带 → 锐化 → 暗角 → 颗粒 → 输出 Rec.709、sRGB 或原生保持 Display P3。具体支持边界见 `color-management.md`。

这是一套可复现的 BLCaptain 运算，不承诺与 Lightroom、醒图、剪映等内部算法逐像素一致。配方 JSON 必须同时保存数值、运算域、顺序和适用媒体；跨软件换算只在 adapter 层表达。

RAW 需要显影；Log 需要准确的相机 Log/Gamut 与技术变换；HDR 需要受控色调映射或 HDR 输出链；P3/Adobe RGB/未知 ICC 图片需要可靠 ICC 管理。以上均不在首版本地自动渲染范围。
