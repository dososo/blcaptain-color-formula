# Foundation-first 执行合同（阶段 0–1 提案）

状态：`proposed_for_phase2`
日期：2026-08-29
边界：本文件是下一阶段的实现与验收合同，**不表示当前引擎已经具备这些能力**。任何条目只有完成 RED→GREEN、真实媒体复验和人工审美门后才能改为已实现。

## 一、产品原则

1. 灰、淡、低反差只是视觉症状，不等于相机 Log。先读取 ICC／色域／传递函数／矩阵／位深与相机元数据，不能靠观感猜输入。
2. Foundation Grade 负责把素材恢复为健康、可创作的中性底片；Creative Look 负责风格。两者不得互相代偿。
3. 用户强度 30／55／80 只能控制 Creative Look。输入解释、Foundation 与 Output Transform 不随风格名称和强度改变。
4. 配方必须声明适用题材、光线、必要观察条件、禁用条件和所需能力。条件不满足时拒绝执行比生成坏片更正确。
5. 全局 RGB／HSL／亮度选区不是人物、肤色、天空、植被、建筑、商品、湿面或反光材质的语义蒙版。
6. 自动指标只证明输入、方向、安全和时序是否退化，不能证明高级、动人、获奖或用户愿意交付。

## 二、不可越级的节点

```text
Input Truth Contract
→ 输入变换／显示参照解释
→ 素材与镜头诊断
→ Foundation Grade
→ Foundation Readiness Gate
→ Scene Fit Gate
→ Creative Look
→ Semantic / Memory-color Protection
→ Shot Match / Temporal Stability
→ Output Transform
→ Technical Gate
→ Human Aesthetic Gate
```

所有评审固定展示：

```text
原片 → Foundation → 最终 Look
```

## 三、节点合同

### 1. Input Truth Contract

输出四态：`display-referred`、`log/raw`、`hdr`、`unknown`。

- 有明确 BT.709／sRGB／Display P3 标签的显示参照素材按标签解释，不因画面低反差而猜成 Log。
- Log／RAW 必须命中相机与编码对应的 Input Transform；未命中则 `BLOCKED_INPUT`。
- 无标签 SDR 只能在用户确认“按常见 SDR 解释”后继续。
- 输入、工作空间与输出条件写入计划指纹和回执。

### 2. Foundation Grade

Foundation 只响应素材缺陷，最少拆为：

- 曝光与中性点；
- 五区影调：black／toe／mid／shoulder／white；
- 白平衡与偏色归中；
- 低彩素材的综合色彩与色彩分离恢复；
- 局部反差与材质可读性；
- 肤色、白衣、中性面、天空、植被等记忆色保护；
- 噪声、剪切、色带和锐化风险。

单镜头“与自己匹配”不能算 Foundation 完成；镜头匹配与基础恢复是两件事。

### 3. Foundation Readiness Gate

以下为 P0 工程种子阈值，必须在留出集校准并版本化，不能写成行业定律：

- 被诊断为低彩、低反差的素材：综合色彩提高 `max(0.01, 20%)`；刻意低彩叙事须显式豁免。
- 影调跨度提高 `max(0.03, 10%)`；刻意低调／高调须显式豁免。
- 局部对比不得相对原片下降超过 3%。
- 白衣、中性物和灰阶不得新增肉眼可见的整体偏色。
- 肤色、天空、植被若存在但无可靠语义证据，自动状态只能是 `manual_review`，不能写通过。
- 任一硬门失败时不进入 Creative Look。

### 4. Scene Fit Gate

每套配方必须声明：

```text
best_for
required_observations
forbidden_conditions
required_capabilities
wrong_scene_fallback
```

- 窄场景配方缺少必要观察条件时，普通用户不推荐、不执行。
- 专家强制错用只能生成“错场景研究预览”，不能叫正式成片。
- 依赖湿面、天空梯度、肤色、镜面或纵深，但当前后端没有对应能力时，返回 `BLOCKED_CAPABILITY`。

### 5. Creative Look

#### 2026-09-07 队长确认的合同修正

- 明暗层次、连续灰阶与量化安全先于固定面积；面积降为观察时，必须显式标记 `area_policy=observation-only`，列出可记录指标与替代安全检查，不得静默删门。
- 纸月不再按百分位拟合硬配额；黑曜、雨墨、高原、鎏金、沙海必须列出实际目标区、保护区和视频时序证据。类别蒙版不等于材质、受光侧或纵深判别。
- 绛雪的视频释放单位是镜头或段落，不是随意插入一两帧；必须有起止、过渡与连续回放证据。
- 以上是合同修订，不代表自动局部或跟踪已经实现，不构成晋级授权。

每套 Look 必须分别声明并执行：

- 五区影调结构；
- 主色、辅色、强调色和中性色；
- 冷暖锚点；
- 彩度随明度的关系；
- 黑位密度与高光去色；
- 纹理、颗粒、锐度和光晕；
- 照片实现与视频实现；
- 禁项与回退。

方向门：

- `colorfulness=increase`：相对 Foundation 至少提高 `max(0.01, 20%)`。
- `colorfulness=preserve`：相对 Foundation 控制在 ±10%。
- `colorfulness=decrease`：只允许用户明确选择低彩／黑白命题。
- 对低彩灰片，综合色彩方向单项失败即阻断；其他声明维度累计两项失败继续阻断。
- Style Bible 自相矛盾、缺核心字段或核心动作无执行算子时直接阻断。

### 6. Semantic / Memory-color Protection

- 人物、肤色、白衣、天空、植被、建筑、商品、水体、湿面与反光材质按能力逐类声明。
- `unavailable`、`available`、`detected`、`executable` 四态不可混用。
- 视频没有跨帧跟踪时，依赖语义局部的 Look 不得降级成全屏染色。
- 蒙版必须保留叠加预览、覆盖率、边界质量、跟踪稳定和人工确认。

### 7. 视频合同

```text
镜头检测与人工复核
→ 每镜头 Foundation
→ 同场景镜头匹配
→ 全片共享 Look
→ 镜头后级 trim
→ 语义蒙版跟踪
→ 非切点时序检查
→ 输出与音频检查
→ 完整连续人工播放
```

单帧或抽帧好看不能外推为视频通过；硬切两侧不做跨镜头平滑。

### 8. 输出与人工门

- 明确目标为 sRGB、Display P3、Rec.709、HDR 或其他显示条件；输出标签、时长、帧率、音频和同步必须正确。
- 技术绿灯后审美状态仍为 `pending`。
- `human_accepted`／`human_rejected` 只能来自显式人工输入，并绑定素材哈希、配方、强度与日期。

## 四、生产、研究与图谱分层

1. `production`：完成声明—执行对齐、适配素材、错场景反例、真实视频和人工门。
2. `research`：公式完整保留，可做研究预览，不进入普通推荐与正式渲染。
3. 风格指纹图谱：同一素材观察差异，只能写“研究诊断预览”。
4. 质量图谱：使用适配题材，走生产门，并展示原片／Foundation／最终 Look。

## 五、晋级样本与人工合同

每套视频 Look 的 P0 晋级集至少包含：

- 6 段真实视频；
- 总时长不少于 180 秒；
- 不少于 20 个镜头；
- 至少 3 类光线；
- 至少 4 段错场景反例；
- 全片连续播放，不只看截图或抽帧。

人工合同：

- “可直接交付”比例不低于 80%；
- “可直接交付＋轻微修改”不低于 90%；
- 鬼片、严重偏色、死黑、发白等灾难结果必须为 0；
- 至少两类不同主体或肤色；
- 照片与视频分别晋级，不能互相外推。

这些比例是项目发布合同，不是自动审美评分或行业事实。

## 六、阶段 2 准入条件

只有以下全部满足才开始改 Foundation／Look 引擎：

- 当前错误图谱已经改为诚实的研究预览表达；
- 六正四负用户反馈已固化且边界清楚；
- 每个根因都有可复现证据；
- RED 规格覆盖输入、Foundation、场景、Look、语义、视频、输出和人工门；
- 所有阈值明确标注为待留出集校准；
- VERSION、安装版和发布状态保持不变。
